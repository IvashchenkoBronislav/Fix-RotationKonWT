# Fix-RotationKonWT

ESP32 WT32-ETH01 “міст” між сервером `Fix-rotation-api` та контролером поворотки `Fix-RotationKon` по UART.

## Протокол UART з `Fix-RotationKon`

### `PACKET_GOTO_AZIMUTH` (0x21)

Підтримуються 2 формати payload (для сумісності зі старими прошивками):

- `len=2`: `angle_lo`, `angle_hi` — поворотка сама обирає напрямок (старий формат).
- `len=3`: `angle_lo`, `angle_hi`, `dir` — поворотка крутить **примусово** у вказаному напрямку.

`dir`:
- `1` — `CW` (за годинниковою)
- `2` — `CCW` (проти годинникової)
- `0` — не використовується в UART payload (у коді `uartSendGoto(angle, 0)` надсилає `len=2`)

## Логіка вибору напряму в цьому проєкті

Якщо від сервера приходить команда `GOTO`, міст:

1) Перевіряє, що цільовий кут входить у дозволений сектор (`allowedFromDeg/allowedToDeg`).
2) Якщо є актуальний статус поворотки (відомий поточний кут), обирає напрямок так, щоб рух від поточного кута до цілі йшов **лише по дозволеній дузі** (не перетинаючи заборонені азімути).
3) Надсилає `PACKET_GOTO_AZIMUTH` у форматі `len=3` з `dir=1/2`.

Якщо поточний кут невідомий/статусу немає — надсилається старий формат `len=2`, і напрямок обирає `Fix-RotationKon`.

## Приклад

Дозволений сектор: `140..30` (перехід через 0) ⇒ дозволено `140..359` і `0..30`.

Поточний кут `30`, ціль `140`:
- короткий шлях `30 -> 140` через “плюс” проходить через `31..139` (заборонено),
- міст відправляє `dir=CCW`, і поворотка їде `30-- … 0 … 359 … 140`.
